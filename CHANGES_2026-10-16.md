# Kona Rust port - 2026-10-16 fixes

Every item below was found by reading the source and then checked against a C Kona built from
upstream (`github.com/kevinlawler/kona`), the same binary whose `tests.c` this port runs. Where C Kona
is quoted, the line was run through both interpreters. A second pass (seven reviewers over the diff,
each finding re-run against C Kona) corrected the first pass in several places; those are marked
*(review)*. Build: `cargo build --release`. No `unsafe`.

## Numbers

| | 2026-10-15 | now |
|---|---|---|
| `cargo test --release` | 61/61 | 61/61 |
| C Kona `tests.c` mismatches (`MAX_C_SUITE_FAILURES`) | 117 | **94** |
| ... passes (`MIN_C_SUITE_PASSED`, new floor) | 1042 | 1071 |
| ... each-pair `':` cases skipped by the harness | 14 | 0 (13 pass) |
| cases where both sides error (used to count as a pass) | hidden | 8, reported on their own line |

`bench/ops_4000000.k` is unchanged within noise on a 4-core Linux box (add 7-11 ms, square 10-17, hit
test 17-28, `+/` 3-4, `_cos` 21-30 ms); the amend row went from ~40 ms to 3 ms. One remaining
`tests.c` difference is deliberate: line 525 expects `(,1)` for `{x,y,z}\[1;();()]` but the C binary
itself prints `1`, and the port follows the binary.

Kona gives a length error for the infix form only.

| Input | Before | Now |
|---|---|---|
| `(!0) +' 1 2 3` (also `+/[0;!0;..]`, `+\[0;!0;..]`) | panic, index out of bounds | `()` / seed |
| `a:`a; a[1]` | stack overflow abort | `limit` |
| `-1 $ "é"`, `1 $ "é"` | panic, byte index inside a char | `,"*"` *(review: the first pass claimed this and had not fixed it)* |
| `(!0) _vs 5` | panic | `!0` |
| `0N#1 2`, `0N_1 2` | capacity-overflow panic (C Kona segfaults) | `domain` / `!0` |
| `-1 4611686018427387904 4#"abcd"` | multiply overflow in debug | `wsfull` *(review)* |
| `100000000000 _draw 2` | allocation abort | `wsfull` |
| `\l a.k` from a.k | stack overflow | `limit` after 124 levels (C Kona's number) |
| `#x +/: 2048#1` with x nested 5000 deep | worker thread stack overflow | `2048` *(review)* |
| `-i` message nested 1M deep | server thread stack overflow | parse error (10 000 levels allowed; the port's own `1:` files read back) *(review)* |
| `-i` C-format header claiming 2 GB | 2 GB zeroed per connection | refused above 100 MB (the port's own limit) |

HTTP connections get a 30 s read timeout and the whole request head is read (ending in CRLF CRLF or
LF LF *(review)*); an IPC connection may idle for any length of time, as with C Kona, but a message
whose header has started must finish within 30 s *(review)*; a failure to start a connection thread
is printed instead of silently dropping the client *(review)*. `json.k` only passes a JSON number
(optional `-`, digits, one point, optional exponent) to `eval`, with blanks around values trimmed;
an unquoted value used to run as K (`{"a":6:"/etc/passwd"}` read the file, `{"a":e}` fetched a global) *(review)*.

## The prompt and the command line

- Plain assignments print nothing (`a:1 2 3`, `a::x`, `a[0]:9`), like C Kona; modifying ones still
  print (`a+:1` shows `2 3 4`) *(review)*. Scripts were already silent.
- `\t expr` prints only the time. It used to print the result too, which is why the 4M-number benches
  dumped 64 MB of floats to the terminal.
- `kona util.k main.k` runs both, in order; only the last used to run. Command-line scripts get the
  same `f` / `f.k` lookup as `\l` *(review)*.
- `\\` inside a script exits the process, as in C Kona (whether the script came from the command line
  or `\l`). A program embedding the library sets `kona::EXIT_ON_SCRIPT_END` to false (the Unreal
  bridge does) and `\\` then ends that script only; it used to call `process::exit` from library code,
  which closed the Unreal editor on any script written for C Kona *(review)*.
- `\l util` finds `util.k` at the prompt too; `\d` set inside a loaded script is put back afterwards;
  `-h` with no value prints a usage line instead of being treated as a script named `-h`.
- `_a` is a list of strings as in C Kona (`("kona";"-i";"5932")`), not a symbol list.
- `\'` shows the adverb help (`\/` still works); the dead `.\`` command and the "2: load C library" line
  (it is disabled) are gone from the help.

## Display

- Floats print with `\p` significant digits, C's `%.7g`, as C Kona does: `0.000123456` stays
  `0.000123456` (was `0.0001235`), `123.456789` is `123.4568`, `0N^2` is `8.507059e+37` (was 38 digits),
  `-0.0` keeps its sign, `\p 0` means all 19 digits *(review)*.
- `$` on a float gives the same text (`$ 0.1+0.2` is `"0.3"`), with C's own spellings `"nan"`, `"inf"`,
  `"-0"` *(review)*.
- `0i` `-0i` `0I` `-0I` instead of `0w` and `9223372036854775807`.
- A one-item list prints with its comma: `,1 2 3`, `,"c"`, `` ,`a `` (they printed like the atom or the inner list).
- Strings print with C-style escapes: `"a\"b"`, `"a\nb"`, `,"\310"` for a non-ASCII byte (a newline
  used to print raw and a non-UTF-8 string as `char_list(len=N)`) *(review)*.
- Symbol lists print with spaces, `` `a `b `c ``; dictionaries print in K3's form, `.((`a;1);(`b;2))`,
  which both interpreters read back (the k4 `` `a`b!1 2 `` is not valid C Kona input) *(review)*.

## Build

- The interpreter stays on the main thread. A spawned thread with a large stack was tried for the
  deeper recursion limit; it made the benches with several 32 MB temporaries twice as slow on Linux.
  `build.rs` instead sets a 64 MB stack reserve for `kona.exe` on Windows (the default there is 1 MB).
  A program embedding the library (`ue/`) must run K on a thread with at least 8 MB of stack, or lower
  `MAX_DEPTH` in `eval.rs`.
- `--features cpp` builds door 2 (the cxx bridge) on any OS; `cpp/kgame_server.exe` (door 3, winsock)
  is only built on Windows, with a warning elsewhere. It used to fail the whole build.

## Test harness

- The 14 `':` cases in `tests.c` were skipped "because they assert the old incorrect behaviour"; they
  were right. They run now and 13 pass.
- A case where both the port and the oracle expression error is no longer a pass; it is reported
  separately and kept out of the ratchet, and a floor on the number of passes (`MIN_C_SUITE_PASSED`)
  catches a change that breaks both sides at once *(review)*.
- `test_lookup_a_and_p` restores `_p` (it left the global print precision at 1234 for whichever test
  ran next).

- `f ghost` / `(1 2 3)[ghost]`: the port's undefined-name quirks (nil, or a created global) differ from
